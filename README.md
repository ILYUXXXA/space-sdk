# ContextShield — прототип антифрод-защиты

Текущий MVP разрабатывается для **Android**: приложение на Kotlin, которое анализирует доступные уведомления и показывает демо-сценарий защиты перевода. Windows UWP-код и веб-страница — уже существующие вспомогательные прототипы; они не входят в текущий план реализации.

## Что уже есть

- **Android:** уведомления проходят локальные правила и дообученный двухголовый RuBERT-tiny2 (риск + тактики) через ONNX Runtime INT8. В 30-минутный зашифрованный граф попадают только категории/оценки, без текста уведомления. Есть ограниченная песочница перевода, три синтетических демонстрационных кейса, узкий opt-in UsageStats-сигнал и проверка выбранного контакта через системный picker/dialer. Ниже доступности порога кнопка демо-перевода активна; выше — приостанавливается.
- **Android + OpenRouter:** ручная перепроверка принимает только категории сигналов и грубые интервалы; текст, имя, номер, package ID и точное время не отправляются. Ключ вводится пользователем и хранится через Android Keystore; лимит — 50 попыток. Облачный ответ отображается как мнение и не меняет решение локальной кнопки.
- **Windows (вне текущего MVP):** в репозитории сохранён отдельный UWP-прототип для справки; развивать его в рамках этого этапа не нужно.
- **Веб:** статическая демо-страница для показа концепции; она не подключена к Android/Windows и не анализирует системные уведомления.
- **Документация:** `ContextShield-подробный-технический-план.md` описывает целевую архитектуру; `docs/user-context-signal-inventory.md` — проверенный список каналов данных, разрешений и ограничений Android/Windows с приоритетами для защиты от мошенничества.
- **План реализации для агента:** `docs/ContextShield-PRD-реализация-агенту.md` — Android-first ТЗ. Помимо уведомлений он описывает ограниченный opt-in анализ запуска приложений удалённого доступа, проверку близкого через системный picker/dialer, обработку изменяемых ников без переноса доверия, граф эпизода, локальную модель, безопасность, облако и критерии готовности. Windows не входит в текущий MVP.
- **Запуск на телефоне:** `docs/ANDROID-DEMO-GUIDE.md` — пошаговая сборка APK, подключение по USB/ADB, включение listener и сценарии показа.
- **Модель и проверка качества:** `docs/model-evaluation.md` — зафиксированные синтетические метрики, SHA-256 модели и ограничения; `ml/` содержит воспроизводимый локальный пайплайн обучения.

## Сборка Android

Требуются Windows, JDK 17, Android SDK Platform 35 и Android Build Tools 34.0.0. Установите Android Studio или эти компоненты отдельно, затем укажите `JAVA_HOME` и `ANDROID_SDK_ROOT` (либо `ANDROID_HOME`).

Из PowerShell в корне клонированного репозитория:

```powershell
./build-android.ps1
```

Скрипт ищет SDK в переменных окружения, стандартной папке Android Studio и локальном каталоге сборочных инструментов проекта. Результат появится как `ContextShield-Android-debug.apk` в корне репозитория. Ручная сборка через Gradle Wrapper:

```powershell
cd android
./gradlew.bat assembleDebug
```

APK будет создан в `android/app/build/outputs/apk/debug/app-debug.apk`.

Чтобы протестировать живые уведомления, установите APK, откройте приложение и вручную разрешите ContextShield доступ к уведомлениям в системных настройках Android. Анализируются только сведения, которые другое приложение действительно публикует в доступной ОС части уведомления; скрытый текст не извлекается. Внутри приложения есть несколько помеченных синтетических кейсов для показа обоих исходов без ручного ввода.

## Сборка Windows

Этот раздел оставлен только для существующего прототипа, вне текущего Android-MVP. Откройте `windows/ContextShield.Windows/ContextShield.Windows.csproj` в Visual Studio с компонентом **Universal Windows Platform development** и Windows SDK 10.0.19041 или совместимым. Для локальной установки пакета Windows потребуются обычные настройки разработки и sideloading на тестовом ПК.

## Веб-демо

Требуется Node.js. Из корня репозитория запустите:

```powershell
node server.js
```

Затем откройте `http://localhost:4173`. Сервер раздаёт локальные статические файлы проекта.

## Границы и статус прототипа

- Это демонстрация анализа доступного контекста, а не интеграция с банковским приложением или платёжной системой. Реальный перевод не исполняется и не блокируется.
- Оценка основана на эвристиках, небольшом synthetic-trained классификаторе и коротком локальном контексте; она может ошибаться. Метрики синтетического holdout не доказывают качество на реальном трафике. До реального применения нужны законно собранные размеченные данные, измерение ложных срабатываний и пропусков, аудит безопасности и проверка на целевых версиях ОС.
- Android-службе уведомлений нужен явный системный доступ. Уведомления могут задерживаться или не содержать текст; Android-ограничения энергосбережения зависят от устройства.
- На Android не реализованы AccessibilityService и MediaProjection. Windows-прототип не читает произвольный экран или содержимое других приложений за пределами уведомлений, доступных через системный API.
- Облачная функция использует ключ пользователя. Не добавляйте ключи, `.env`, личные уведомления или реальные пользовательские данные в Git. Фильтрация идентификаторов локальная и эвристическая, поэтому перед включением облачной отправки проверьте очищаемый запрос и условия выбранной модели/провайдера.
- В репозитории сохранены имеющиеся APK как исторические debug-сборки. Для актуального исходного кода пересоберите APK скриптом; APK не является релизом Google Play.
