# ContextShield — прототип антифрод-защиты

В этом репозитории собраны материалы демонстрационного проекта: Android-приложение на Kotlin, Windows UWP-монитор уведомлений на C#, локальная веб-демонстрация и подробный технический план.

## Что уже есть

- **Android:** локальная оценка риска уведомлений, короткая история сигналов, график риска за окно наблюдения, объяснение факторов и экран-песочница с кнопкой «Перевести». При высоком риске демо-кнопка блокируется. Экран не подключён к банку и не перемещает настоящие деньги.
- **Android + OpenRouter:** облачная перепроверка запускается вручную из приложения. Перед отправкой фрагменты очищаются на устройстве; ключ вводится пользователем и хранится через Android Keystore. Установлен локальный предел в 50 попыток. Это не гарантия полного удаления всех идентификаторов и не замена политике конфиденциальности провайдера.
- **Windows:** отдельный UWP-прототип читает доступные Windows toast-уведомления после системного разрешения и показывает локальные предупреждения. Экран перевода и облачная перепроверка для Windows пока не реализованы.
- **Веб:** статическая демо-страница для показа концепции; она не подключена к Android/Windows и не анализирует системные уведомления.
- **Документация:** `ContextShield-подробный-технический-план.md` описывает целевую архитектуру; `docs/user-context-signal-inventory.md` — проверенный список каналов данных, разрешений и ограничений Android/Windows с приоритетами для защиты от мошенничества.
- **План реализации для агента:** `docs/ContextShield-PRD-реализация-агенту.md` — Android-first ТЗ. Помимо уведомлений он описывает ограниченный opt-in анализ запуска приложений удалённого доступа, проверку близкого через системный picker/dialer, обработку изменяемых ников без переноса доверия, граф эпизода, локальную модель, безопасность, облако и критерии готовности. Windows не входит в текущий MVP.

## Сборка Android

Требуются Windows, JDK 17, Android SDK Platform 35 и Android Build Tools 34.0.0. Установите Android Studio или эти компоненты отдельно, затем укажите `JAVA_HOME` и `ANDROID_SDK_ROOT` (либо `ANDROID_HOME`).

Из PowerShell в корне клонированного репозитория:

```powershell
./build-android.ps1
```

Скрипт ищет SDK в переменных окружения, стандартной папке Android Studio и локальном каталоге сборочных инструментов проекта. Результат появится как `ContextShield-Android-debug.apk` в корне репозитория. Ручная сборка через Gradle Wrapper:

```powershell
cd android
./gradlew.bat assembleDebug
```

APK будет создан в `android/app/build/outputs/apk/debug/app-debug.apk`.

Чтобы протестировать уведомления, установите APK, откройте приложение и вручную разрешите ContextShield доступ к уведомлениям в системных настройках Android. Анализируются только сведения, которые другое приложение действительно публикует в доступной ОС части уведомления; скрытый текст не извлекается.

## Сборка Windows

Откройте `windows/ContextShield.Windows/ContextShield.Windows.csproj` в Visual Studio с компонентом **Universal Windows Platform development** и Windows SDK 10.0.19041 или совместимым. Это UWP-прототип; для локальной установки пакета Windows потребуются обычные настройки разработки и sideloading на тестовом ПК. Работа мониторинга зависит от разрешения `UserNotificationListener`, доступности toast-уведомлений и фонового запуска в Windows.

## Веб-демо

Требуется Node.js. Из корня репозитория запустите:

```powershell
node server.js
```

Затем откройте `http://localhost:4173`. Сервер раздаёт локальные статические файлы проекта.

## Границы и статус прототипа

- Это демонстрация анализа доступного контекста, а не интеграция с банковским приложением или платёжной системой. Реальный перевод не исполняется и не блокируется.
- Оценка основана на эвристиках и коротком локальном контексте; она может ошибаться. До реального применения нужны размеченные тестовые данные, измерение ложных срабатываний и пропусков, аудит безопасности и проверка на целевых версиях ОС.
- Android-службе уведомлений нужен явный системный доступ. Уведомления могут задерживаться или не содержать текст; Android-ограничения энергосбережения зависят от устройства.
- На Android не реализованы AccessibilityService и MediaProjection. Windows-прототип не читает произвольный экран или содержимое других приложений за пределами уведомлений, доступных через системный API.
- Облачная функция использует ключ пользователя. Не добавляйте ключи, `.env`, личные уведомления или реальные пользовательские данные в Git. Фильтрация идентификаторов локальная и эвристическая, поэтому перед включением облачной отправки проверьте очищаемый запрос и условия выбранной модели/провайдера.
- В репозитории сохранены имеющиеся APK как исторические debug-сборки. Для актуального исходного кода пересоберите APK скриптом; APK не является релизом Google Play.
