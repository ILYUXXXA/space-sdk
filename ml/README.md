# Локальное обучение Android-модели ContextShield

## Что обучается

`cointegrated/rubert-tiny2` дообучается как компактный multi-task encoder на четыре класса риска (`safe`, `needs_check`, `suspicious`, `dangerous`) и тринадцать тактик. Это не генеративная LLaMA/чат-модель. На Android inference выполняется локально через ONNX Runtime Mobile; обычный разбор уведомления не отправляет текст в сеть.

Обучение использует два источника:

1. Русские 1,124 синтетических/шаблонных примера из зафиксированной версии `dokster/adaption-scam-dataset-ru-en-v1` (Apache-2.0).
2. 80 коротких проектных синтетических сообщений из `ml/data/curated_ru_train.jsonl`: бытовые просьбы и безобидные денежные расчёты, неясные обращения, давление/имитация, запросы кодов и доступа. Файл не содержит сообщений пользователя.

Сначала записи группируются по сценарию и делятся на train/validation/test. Только после этого к training rows добавляется по одной детерминированной поверхностной вариации: разговорные синонимы, `ё/е`, регистр/пробелы/пунктуация и редкие латинские look-alike символы. Валидация и test остаются без аугментаций. Скрипт сравнивает также word/char TF-IDF baseline.

Оценка включает отдельный 316-строчный синтетический boundary-набор и 32 проектных коротких сообщения в `ml/data/challenge_suite_ru.jsonl`. Ни один из этих двух eval-файлов не участвует в обучении. Метрики ограничены synthetic распределениями; качество на пользовательских чатах пока неизвестно.

## Запуск на этой машине

В каталоге `outputs`:

```powershell
python -m venv ml/.venv
ml/.venv/Scripts/python.exe -m pip install -r ml/requirements.txt
ml/.venv/Scripts/python.exe ml/download_assets.py
ml/.venv/Scripts/python.exe ml/train.py
ml/.venv/Scripts/python.exe ml/evaluate_operating_point.py
ml/.venv/Scripts/python.exe ml/evaluate_challenge_suite.py
```

`download_assets.py` скачивает базовую модель и лицензированный корпус по зафиксированным Hugging Face revisions и сверяет SHA-256 крупных файлов. `train.py` делает group split, обучает baseline и multitask encoder, выбирает checkpoint по validation, экспортирует и динамически квантует ONNX, сравнивает модель на held-out test и отдельном boundary eval, затем копирует INT8 runtime модель, vocabulary и metadata в Android assets.

Оба eval-скрипта только считают результаты; они не выбирают пороги и не меняют модель. Оценочные примеры из challenge suite написаны для нескольких классов и не содержат приватных сообщений или скриншотов пользователя.

Сырые public-файлы находятся в `ml/data/raw/` и исключены из Git. В APK не кладутся исходные датасеты. Хеши источников, типы лицензий и ограничения зафиксированы в `ml/dataset_registry.yaml`.

## Ограничения

- Все обучающие и тестовые сообщения синтетические; их метрики не являются accuracy на реальном трафике.
- Challenge suite небольшой, проектный и не является независимым реальным benchmark.
- Оценки модели не доказывают личность отправителя, факт мошенничества или намерение.
- Nickname не объединяет и не наследует доверие; без официального устойчивого account ID continuity остаётся `UNKNOWN`.
- Для надёжного шага нужны законно собранные consented сообщения, ручная разметка, hard negatives, frozen holdout и измерение ложных тревог на большой доброкачественной выборке.
- Перед настоящим применением нужно измерить latency/RAM на целевом Xiaomi; модель около 29 MB, итоговый universal APK будет больше.
- Реальные переводы не подключены. Модель не должна единолично блокировать денежную операцию.
